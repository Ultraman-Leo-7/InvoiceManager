# 发票管理工具

一个面向 Windows 的个人发票管理小工具。把程序放进发票 PDF 文件夹后直接运行，可以管理本地电子发票、从 QQ 邮箱获取京东发票、记录自己买过的东西、按价格自动核对发票，并在需要时导出 Excel。

> 当前仍处于测试版阶段。推荐从 GitHub **Releases** 下载最新 Windows 版本进行使用。

---

# 第一部分：小白快速使用

这一部分只讲“怎么用”。第一次使用按顺序做即可。

## 1. 下载并放到发票文件夹

1. 打开本项目 GitHub 的 **Releases** 页面。
2. 下载最新 Windows 版程序。
3. 新建或选择一个专门存放发票 PDF 的文件夹。
4. 把程序放进这个文件夹。
5. 双击程序启动。

程序会把 **exe 所在目录** 当作当前发票目录，所以最简单的用法就是：

```text
发票文件夹/
├─ InvoiceManager.exe
├─ 发票1.pdf
├─ 发票2.pdf
└─ ...
```

首次启动时，程序会自动创建自己的数据库文件，用来保存设置、购买记录、人工确认和备注。

---

## 2. 看本地已有发票

程序启动后会自动扫描当前目录中的 PDF 发票。

默认发票表显示：

- 文件名
- 项目名称
- 价税合计
- 购买匹配
- 人工确认
- 备注

如果刚放进新的 PDF，通常不用手动操作，程序会自动检测文件夹变化并刷新。

如果想立即刷新，也可以点：

**刷新发票文件夹**

---

## 3. 设置 QQ 邮箱，用来获取京东发票

点击：

**设置**

填写：

- QQ 邮箱
- QQ 邮箱 16 位授权码

授权码保存后，设置页面不会再次显示明文。以后授权码输入框保持空白即可继续使用之前保存的授权码。

然后回到主界面，点击：

**从QQ邮箱获取京东发票**

可选择：

- 从上次成功获取之后
- 自定义起始时间
- 扫描全部历史收件箱

自定义时间支持：

```text
2026-08-01
```

表示从 `2026-08-01 00:00` 开始。

也支持：

```text
2026-08-01 13:25
```

表示从 `2026-08-01 13:25` 开始。

下载完成后，京东发票 PDF 会直接进入当前发票文件夹，并自动出现在发票表中。

## 4. 记录自己买过的东西

切换到：

**购买记录**

例如买了一根数据线：

```text
名称：数据线
商品价格：7.00
有快递费：不勾选
```

点击 **新增**。

如果买了一个京东背包：

```text
名称：背包
商品价格：74.00
有快递费：勾选
快递费：6.00
```

程序会把它理解为需要两张发票：

- 商品发票：74.00 元
- 快递费发票：6.00 元

因为京东商品和快递费可能分别开发票，所以不会把两项相加后去找一张 80 元发票。

购买记录支持：

- 新增
- 编辑
- 删除
- Ctrl / Shift 多选后批量删除
- 一键清除全部购买记录

---

## 5. 看哪些东西有发票、哪些还没有

程序只按 **价格** 自动匹配，不看商品名称。

例如：

```text
购买记录：数据线 7.00
发票金额：7.00
```

则自动匹配。

购买记录页面会同时显示：

- 已完整匹配的购买记录
- 已记录购买，但缺少对应发票的内容
- 有发票，但没有对应购买记录的内容

发票管理页面的 **购买匹配** 一列也会显示类似：

```text
✓ 背包（商品）
✓ 背包（快递费）
```

## 6. 人工确认一张发票

如果你自己已经核对过某张发票，可以选中它，然后点击：

**人工确认标记**

表格中的“人工确认”会出现 `✓`。

再次对已经全部确认的选中项执行该按钮，会取消这些确认标记。

人工确认状态不是从 PDF 自动提取出来的，而是专门保存的人工数据。以后增加、删除或刷新其他发票时，不会把已经保存的确认状态一起重置。

## 8. 删除发票

**删除选中发票**

确认后会：

2. 自动刷新发票列表；

- 发票汇总 Sheet

# 第二部分：完整功能与实现细节

这一部分用于以后回顾项目设计。功能修改时应同步维护本节，避免随着版本迭代忘记程序已经支持什么。

## A. 当前目录与数据源

- 程序把 **exe 所在目录** 作为发票目录。
- 当前目录中的 `*.pdf` 是当前有效发票的数据源。
- 程序启动后会自动扫描 PDF。
- 程序保留“刷新发票文件夹”按钮，可立即手动触发扫描。
- 除手动刷新外，程序还会 **每 2 秒检查一次当前目录中的 PDF 文件状态**。
- 检查依据包括文件名、文件大小、修改时间。
- 检测到 PDF 新增、删除或变化后，会自动触发刷新。

### PDF 刷新规则

- 新增 PDF：解析并加入发票列表。
- 已存在且内容未变化：复用 SQLite 中已有解析结果，不重复解析。
- PDF 内容变化：重新解析自动字段。
- 同一份 PDF 改名但内容相同：通过内容哈希识别后继续复用记录。
- PDF 从文件夹删除：该发票不再作为当前有效发票显示。
- 同一份 PDF 以后再次放回：如果内容哈希相同，可以继续复用原有数据库记录，包括人工确认和备注。

---

## B. PDF 发票解析

程序当前通过 `PyMuPDF` 读取 PDF 文字层和文字坐标，提取中国电子发票中的信息。

可识别并可在设置中选择显示的字段：

- 文件名
- 发票号码
- 开票日期
- 购买方名称
- 销售方名称
- 项目名称
- 价税合计
- 金额（不含税）
- 税额
- 开票人
- 提取状态

默认显示字段：

- 文件名
- 项目名称
- 价税合计

另外 GUI 固定增加：

- 购买匹配
- 人工确认
- 备注

如果 PDF 没有可用文字层或部分字段无法识别，会在“提取状态”中给出需要复核的提示。

## C. SQLite 数据库与人工数据保护

程序不再把 Excel 当数据库，而是在当前发票文件夹创建内部 SQLite 数据库：

```text
.invoice_manager.db
```

在 Windows 下会尝试把这个数据库文件设置为隐藏文件，减少日常文件夹中的干扰。

数据库中保存两类信息。

### 自动数据

来自 PDF 解析，例如：

- 发票号码
- 日期
- 项目名称
- 价税合计
- 销售方
- 提取状态

这些字段在 PDF 内容变化后可以重新解析并更新。

### 人工数据

由用户自己维护，例如：

- 人工确认
- 备注
- 购买记录
- QQ 邮箱设置

这些数据不会因为重新解析 PDF 而被自动字段覆盖。

这也是从旧版“Excel 每次重建”改成 SQLite 的主要原因。

---

## D. 人工确认与备注

### 人工确认

- 发票可以人工打 `✓` 标记。
- 支持 Ctrl / Shift 多选后批量确认。
- 如果选中的发票已经全部确认，再执行“人工确认标记”会取消这些确认。
- 人工确认保存在 SQLite 中。
- 刷新文件夹、重新解析或添加其他发票不会清空确认状态。

### 备注

- 每张发票都可以添加独立备注。
- 编辑备注时要求只选择一张发票。
- 备注保存在 SQLite 中。
- 发票重新扫描时不会覆盖备注。

---

## E. QQ 邮箱京东发票获取

当前已实现的邮件来源：

```text
QQ 邮箱 -> 京东电子发票
```

以后可以继续在代码中增加其他邮箱或其他平台的发票获取模块，而不是让普通用户在 exe 中自己编写规则。

### QQ IMAP

使用：

```text
imap.qq.com:993
SSL/TLS
```

登录使用：

- QQ 邮箱地址
- QQ 邮箱 16 位授权码

不是 QQ 登录密码。

### 授权码保存方式

- QQ 邮箱地址会保存在程序数据库中。
- 16 位授权码只需要首次输入或需要更换时重新输入。
- 授权码保存以后，设置界面 **不会回显明文**。
- 设置页输入框为空时表示继续保留并使用之前的授权码。
- Windows 下授权码使用 **DPAPI** 加密后再保存到 SQLite。
- DPAPI 密文通常只能由保存它的 Windows 用户上下文解密。
- 设置页提供“清除授权码”按钮。

### 邮件扫描范围

当前只扫描：

```text
QQ 邮箱 INBOX（收件箱）
```

不会自动扫描垃圾箱、已删除邮件或用户自己移动到其他文件夹中的邮件。

筛选京东邮件时当前使用：

- 发件人：`customer_service@jd.com`
- 主题包含：`电子发票已开具`

### 起始时间

支持：

- 全部历史收件箱
- 自定义起始时间
- 从上次成功获取之后

自定义输入：

```text
YYYY-MM-DD
```

默认该日 `00:00`。

也支持：

```text
YYYY-MM-DD HH:MM
```

精确到分钟。

IMAP 的 `SINCE` 本身只能按“天”筛选，所以程序先用 IMAP 按日期缩小范围，再读取邮件的 `Date` 头并转换为本机时区，二次过滤到分钟。

### “上次成功获取”机制

- 程序记录最近一次完整成功获取的开始时间。
- 如果本次存在下载失败项，不会推进“上次成功获取”时间。
- 这样下一次可以继续重试，降低因为某一张失败而永久跳过邮件的风险。

### PDF 链接提取与下载

- 京东发票邮件中的 PDF 当前不是普通附件，而是邮件 HTML 中的“发票PDF文件下载”链接。
- 程序解析邮件 HTML，提取对应下载链接。
- 尝试从主题提取京东订单号。
- 尝试从邮件上下文提取发票号码。
- 下载前后均有去重逻辑。
- 已存在同名目标文件时会跳过。
- 下载后还会通过 PDF 内容 SHA256 防止相同文件重复保存。
- 下载结果必须以 `%PDF-` 开头，否则视为非 PDF 响应并记录失败。
- 每个下载请求当前最多重试 3 次。

## I. 发票删除

发票管理页面提供：

**删除选中发票**

支持单选和多选。

删除前会弹出二次确认，并显示部分即将删除的文件名。

确认后：

- 实际调用文件删除操作移除当前目录中的 PDF；
- 不只是删除数据库记录；
- 删除后自动重新扫描文件夹；
- 发票表自动更新；
- 购买匹配状态自动重新计算。

## K. 购买记录与发票价格匹配

当前设计故意保持简单：

> **只根据价格匹配。**

不会使用：

- 商品名称
- 商家名称
- 订单号
- 日期

金额会先换算成“分”的整数后再比较，避免直接使用浮点数进行金额相等判断。

例如：

```text
购买记录：数据线 7.00
发票：7.00
```

则认为可以匹配。

### 京东快递费

如果购买记录勾选“有快递费”：

```text
背包
商品：74.00
快递费：6.00
```

程序会拆成两个独立待匹配组成项：

```text
商品 74.00
快递费 6.00
```

分别寻找对应发票。

### 一对一原则

- 一张发票最多匹配一个购买组成项。
- 一个购买组成项最多匹配一张发票。
- 如果存在多张价格完全相同的发票和多条同价购买记录，程序按购买记录 ID 和发票文件名顺序依次配对。

由于当前只按价格匹配，同价商品较多时，程序只能保证金额数量上的一对一对应，不能保证真实业务含义一定对应正确。这种情况仍建议人工复核。

## O. 自动发布 Windows exe

项目使用 GitHub Actions 自动构建 Windows 版本。

主要流程：

```text
代码更新到 main
↓
GitHub Windows Runner
↓
安装 Python 和依赖
↓
语法 / import 检查
↓
PyInstaller 单文件打包
↓
上传构建产物
↓
自动创建 GitHub Pre-release
```

普通使用者不需要自己安装 Python、PyMuPDF、openpyxl 或 PyInstaller，直接从 Releases 下载 exe 即可。

## Q. 数据与安全说明

- 发票 PDF 和 SQLite 数据库默认都只保存在本地当前文件夹。
- QQ 邮箱授权码不会上传到 GitHub。
- 授权码不会写进源代码。
- Windows 下授权码使用 DPAPI 加密后写入本地数据库。
- 设置页面不会把已保存授权码重新显示出来。
- GitHub Release 中的 exe 目前没有商业代码签名证书，因此 Windows 可能显示“未知发布者”或 SmartScreen 提示。
- 删除发票功能会实际删除本地 PDF，应谨慎使用。
