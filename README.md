# InvoiceManager

**一个面向 Windows 的个人电子发票管理工具。**

InvoiceManager 不只是把 PDF 转成 Excel，而是把下面这套流程放进一个本地 GUI 中：

```text
发票收集 → PDF 解析 → 发票管理 → 购买记录 → 发票核对 → Excel 导出
```

当前主要支持中国电子发票 PDF、QQ 邮箱中的京东电子发票，以及基于价格的购买记录/发票核对。

> 项目仍在持续迭代中。建议从 GitHub Releases 下载最新 Windows 版本，并在重要操作前保留自己的发票备份。

## 下载

普通用户不需要安装 Python。

前往仓库 **Releases** 页面，下载：

```text
InvoiceManager-Windows-x64.exe
```

把 exe 放到你的发票 PDF 文件夹中，双击即可运行。

> 当前 exe 没有商业代码签名证书，Windows 可能显示“未知发布者”或 SmartScreen 提示。

## 功能亮点

| 功能 | 说明 |
|---|---|
| PDF 发票管理 | 扫描当前目录中的电子发票 PDF，并提取常用字段 |
| 自动刷新 | 每 2 秒检测 PDF 的新增、删除和变化，检测到变化后自动刷新 |
| QQ 邮箱京东发票获取 | 使用 QQ 邮箱 + 16 位授权码批量获取京东电子发票 |
| 购买记录 | 记录商品名称、商品价格、是否有快递费及快递费金额 |
| 发票核对 | 当前按价格精确匹配，商品价与快递费分别匹配 |
| 人工确认与备注 | 人工状态保存在 SQLite 中，不会因重新扫描 PDF 而丢失 |
| 搜索与排序 | 支持全字段/指定字段搜索，点击表头升降序排序 |
| 多选与批量操作 | Ctrl / Shift 多选，支持批量确认、批量删除 |
| Excel 导出 | SQLite 保存长期状态，Excel 只作为按需导出结果 |
| 本地优先 | 发票、购买记录和数据库默认都保存在本地当前目录 |

## 隐私提醒

InvoiceManager 会处理发票和邮箱授权信息，请注意：

- 不要把自己的 PDF 发票、`.invoice_manager.db` 或包含真实隐私的截图上传到公开 Issue。
- QQ 邮箱授权码不会写进源代码，也不会上传到 GitHub。
- Windows 下授权码使用 DPAPI 加密后保存在本地 SQLite 中。
- 设置页面不会重新显示已经保存的授权码明文。
- 提交 Bug 截图前，请打码姓名、税号、地址、电话、邮箱、订单号等敏感信息。

详细隐私说明见 `PRIVACY.md`，安全问题见 `SECURITY.md`。

# 第一部分：小白快速使用

这一部分只讲怎么用。第一次使用按顺序操作即可。

## 1. 下载并放进发票文件夹

1. 打开本项目 GitHub 的 **Releases** 页面。
2. 下载最新的 `InvoiceManager-Windows-x64.exe`。
3. 新建或选择一个专门存放发票 PDF 的文件夹。
4. 把 exe 放进这个文件夹。
5. 双击程序启动。

例如：

```text
发票文件夹/
├─ InvoiceManager-Windows-x64.exe
├─ 发票1.pdf
├─ 发票2.pdf
└─ ...
```

程序把 **exe 所在目录** 作为当前发票目录。

首次运行后，会在该目录创建内部数据库：

```text
.invoice_manager.db
```

数据库用于保存设置、购买记录、人工确认、备注等长期状态。

## 2. 查看本地已有发票

程序启动后会自动扫描当前目录中的 PDF。

默认发票表主要显示：

- 文件名
- 项目名称
- 价税合计
- 购买匹配
- 人工确认
- 备注

如果你往文件夹里新增、删除或替换 PDF，程序通常会在几秒内自动发现。

如果想立即重新扫描，可以点击：

**刷新发票文件夹**

## 3. 设置 QQ 邮箱并获取京东发票

点击：

**设置**

填写：

- QQ 邮箱
- QQ 邮箱 16 位授权码

这里使用的是 QQ 邮箱给第三方客户端生成的 **授权码**，不是 QQ 登录密码。

授权码保存成功后：

- 设置页面不会再次显示它的明文；
- 输入框保持空白是正常现象；
- 留空保存会继续使用之前保存的授权码；
- Windows 下保存值使用 DPAPI 加密。

然后点击：

**从QQ邮箱获取京东发票**

当前支持三种范围：

- 从上次成功获取之后
- 自定义起始时间
- 扫描全部历史收件箱

自定义时间支持：

```text
2026-08-01
```

表示从 `2026-08-01 00:00` 开始。

也支持：

```text
2026-08-01 13:25
```

表示从该分钟开始。

下载完成后，京东发票 PDF 会直接保存到当前发票文件夹，并进入发票列表。

## 4. 添加购买记录

切换到：

**购买记录**

例如：

```text
名称：数据线
商品价格：7.00
有快递费：不勾选
```

点击 **新增**。

如果商品有单独快递费，例如：

```text
名称：背包
商品价格：74.00
有快递费：勾选
快递费：6.00
```

程序会把它看成两个独立待匹配项：

```text
商品：74.00
快递费：6.00
```

分别寻找对应发票，而不是去找一张 80 元发票。

购买记录支持：

- 新增
- 编辑
- 删除
- Ctrl / Shift 多选后批量删除
- 一键清空全部购买记录

清空购买记录不会删除 PDF 发票。

## 5. 看哪些购买已经有发票

当前匹配规则很简单：

> **只按价格精确匹配。**

例如：

```text
购买记录：数据线 7.00
发票金额：7.00
```

程序会尝试将二者配对。

购买记录页面会显示：

- 每条购买记录的商品发票
- 快递费发票
- 是否完整匹配
- 已记录购买但缺少发票的组成项
- 当前存在但没有对应购买记录的发票

发票管理页的“购买匹配”列也会显示对应购买名称。

如果存在多个完全相同价格的商品或发票，程序只能按顺序做一对一匹配，无法仅凭价格判断真实业务对应关系，这种情况需要人工复核。

## 6. 人工确认与备注

### 人工确认

选中一张或多张发票，点击：

**人工确认标记**

已确认的发票会显示 `✓`。

如果选中的发票已经全部处于确认状态，再执行一次会取消这些确认。

人工确认保存在 SQLite 中，不会因为重新扫描其他 PDF 而被重置。

### 备注

选中一张发票后点击：

**编辑备注**

备注同样保存在 SQLite 中。

## 7. 搜索、排序和多选

### 搜索

发票页面可以选择搜索范围：

- 全部字段
- 文件名
- 项目名称
- 价税合计
- 发票号码
- 开票日期
- 购买方名称
- 销售方名称
- 金额（不含税）
- 税额
- 开票人
- 提取状态
- 购买匹配
- 人工确认
- 备注

例如可以搜索：

```text
6.00
```

金额搜索会使用两位小数形式。

当前是字符串包含匹配，因此搜索 `6` 也可能命中 `6.00`、`16.90` 等内容。

另外还有两个快速筛选：

- 只看未人工确认
- 只看未匹配购买记录的发票

### 排序

点击任意可见表头即可排序。

同一列连续点击会在升序 / 降序之间切换。

金额字段按数值排序，其他字段按文本排序。

购买记录相关表格同样支持表头排序。

### 多选

Windows 下支持：

- `Ctrl + 单击`：不连续多选
- `Shift + 单击`：连续多选

## 8. 删除发票

选中一张或多张发票，点击：

**删除选中发票**

程序会先弹出二次确认。

确认后会：

1. 实际删除当前目录中的 PDF 文件；
2. 重新扫描文件夹；
3. 更新发票列表；
4. 重新计算购买匹配状态。

这不是“只从表格隐藏”，而是真实删除文件。

程序目前没有内置撤销/回收站恢复机制，所以请谨慎操作。

## 9. 导出 Excel

平时不需要维护 Excel。

需要表格时点击：

**导出 Excel**

程序会生成：

```text
发票汇总.xlsx
```

其中包含：

- 发票汇总 Sheet
- 购买记录 Sheet

SQLite 数据库才是长期状态存储，Excel 是按需导出结果。

如果 Excel/WPS 正占用该文件，程序会提示先关闭后再导出。

# 第二部分：完整功能与实现细节

这一部分用于用户、贡献者和维护者以后回顾程序设计。**每次增加、删除或改变用户可见功能时，都应同步更新本节。**

## A. 当前目录与自动刷新

- exe 所在目录就是发票目录。
- 当前目录中的 `*.pdf` 是当前有效发票源。
- 启动后自动扫描一次。
- 提供“刷新发票文件夹”按钮，可立即手动扫描。
- 程序还会 **每 2 秒检查一次 PDF 文件状态**。
- 检查内容包括：文件名、文件大小、修改时间。
- 检测到新增、删除或变化后，会自动触发刷新。

PDF 刷新规则：

- 新增 PDF：计算 SHA256，解析并加入当前列表。
- 已存在且解析器版本未变化：直接复用 SQLite 中已有解析结果。
- PDF 内容变化：重新解析自动字段。
- 同内容改名：通过内容哈希识别，继续复用该记录。
- PDF 从文件夹删除：数据库历史记录仍可保留，但当前列表不再显示。
- 同一内容以后重新放回：可以继续复用之前的人工确认和备注。

## B. PDF 发票解析

程序使用 `PyMuPDF` 读取 PDF 文字层及文字坐标。

当前主要面向带可读取文字层的中国电子发票，不是通用 OCR 软件。

可识别并可在设置中选择显示的字段包括：

- 文件名
- 发票号码
- 开票日期
- 购买方名称
- 销售方名称
- 项目名称
- 价税合计
- 金额（不含税）
- 税额
- 开票人
- 提取状态

默认显示：

- 文件名
- 项目名称
- 价税合计

GUI 固定增加：

- 购买匹配
- 人工确认
- 备注

如果 PDF 没有可读取文字层或部分字段无法可靠提取，“提取状态”会提示需要复核。

## C. SQLite 数据库

数据库文件：

```text
.invoice_manager.db
```

Windows 下程序会尝试把该文件设为隐藏文件。

数据库保存两类数据。

### 自动数据

来自 PDF，例如：

- 发票号码
- 开票日期
- 买方/卖方
- 项目名称
- 价税合计
- 不含税金额
- 税额
- 开票人
- 提取状态

这些字段在 PDF 或解析器变化后可以重新生成。

### 人工数据

包括：

- 人工确认
- 备注
- 购买记录
- QQ 邮箱设置
- 授权码密文
- 上次邮箱获取时间

这些内容不会因为普通 PDF 重解析而被自动字段覆盖。

## D. QQ 邮箱授权码保存

QQ 邮箱集成使用：

```text
imap.qq.com:993
SSL/TLS
```

需要：

- QQ 邮箱地址
- QQ 邮箱 16 位授权码

授权码不是 QQ 登录密码。

保存规则：

- 邮箱地址保存到本地 SQLite。
- 授权码保存后，设置页面不回显明文。
- 输入框为空时表示继续使用之前保存的授权码。
- Windows 下授权码通过 DPAPI 加密后保存。
- DPAPI 加密内容通常与当前 Windows 用户环境绑定。
- 如果把数据库复制到其他电脑或其他 Windows 用户下，可能需要重新输入授权码。
- 设置页提供清除授权码功能。

## E. QQ 邮箱 → 京东发票获取

当前邮件来源：

```text
QQ 邮箱 INBOX → 京东电子发票
```

当前只扫描 `INBOX` 收件箱，不自动扫描垃圾箱、已删除或其他用户自建文件夹。

京东邮件当前筛选规则：

- 发件人：`customer_service@jd.com`
- 主题包含：`电子发票已开具`

支持三种时间范围：

- 全部历史收件箱
- 自定义起始时间
- 从上次成功获取之后

自定义时间支持：

```text
YYYY-MM-DD
YYYY-MM-DD HH:MM
```

由于 IMAP `SINCE` 原生只能按“天”筛选，程序会：

1. 用 IMAP 按日期缩小范围；
2. 再读取邮件 `Date` 头；
3. 转换到本机时区；
4. 二次过滤到分钟。

“上次成功获取”机制：

- 程序保存最近一次完整成功获取的时间。
- 如果本次存在下载失败项，不推进该时间。
- 下一次可以继续重试失败范围，降低漏发票概率。

京东 PDF 下载：

- 当前主要从邮件 HTML 中寻找“发票PDF文件下载”链接，而不是普通邮件附件。
- 尝试从邮件中提取订单号、发票号码。
- 已存在同名目标文件时跳过。
- 下载后使用 SHA256 再次检查重复内容。
- 响应必须以 `%PDF-` 开头，否则视为异常响应。
- 当前每个下载请求最多重试 3 次。

## F. 购买记录与匹配规则

每条购买记录包括：

- 名称
- 商品价格
- 是否有快递费
- 快递费
- 创建时间
- 更新时间

当前匹配规则故意保持简单：

> **只根据价格匹配。**

不会使用商品名称、商家、订单号、日期等业务信息。

金额会转换为整数“分”后比较，避免浮点数直接比较金额。

如果存在快递费：

```text
商品：74.00
快递费：6.00
```

会拆成两个独立组成项，分别寻找 74 元和 6 元发票。

一对一规则：

- 一张发票最多匹配一个购买组成项。
- 一个购买组成项最多匹配一张发票。
- 多条同价购买/发票按购买记录 ID、发票文件名顺序依次配对。

因此同价商品很多时，只能保证金额数量上的一对一，不能保证业务上一定是正确那一单。

## G. 搜索

支持“搜索范围 + 搜索内容”。

搜索范围包括自动字段、购买匹配、人工确认和备注。

“全部字段”会把这些信息一起参与搜索。

金额格式化为两位小数后参与搜索。

另外支持：

- 只看未人工确认
- 只看未匹配购买记录的发票

## H. 表头排序

发票表：

- 点击表头排序。
- 连续点击同一列切换升序/降序。
- 金额字段按数值排序。
- 其他字段按文本排序。

购买记录主表，以及“缺少发票”“未对应发票”等表格，同样支持表头排序。

## I. 多选与批量操作

发票表和购买记录表使用扩展多选模式。

支持：

- `Ctrl + 单击`：不连续多选
- `Shift + 单击`：连续多选

可批量执行：

- 人工确认 / 取消人工确认
- 删除发票
- 删除购买记录

备注编辑和购买记录编辑属于单条编辑，因此要求只选一项。

## J. 发票删除

“删除选中发票”支持单选和多选。

删除前会二次确认。

确认后实际删除本地 PDF，而不是仅删除数据库记录。

为降低误删路径风险，程序会检查目标文件仍位于当前发票目录下。

删除后自动重新扫描，并重新计算购买匹配。

当前没有程序内撤销机制。

## K. Excel 导出

Excel 只是导出格式，不是程序主数据库。

输出文件：

```text
发票汇总.xlsx
```

发票汇总 Sheet 包括：

- 设置中选中的发票字段
- 购买匹配
- 人工确认
- 备注

购买记录 Sheet 包括：

- 名称
- 商品价格
- 有快递费
- 快递费
- 商品发票
- 快递费发票
- 完整匹配

## L. Windows 构建与发布

普通代码变更和正式发布现在分开处理。

### CI

对 `main` 的相关代码提交和 Pull Request 自动运行：

```text
语法检查
↓
import 检查
↓
pytest 单元测试
```

### Release

发布版本时手动运行 GitHub Actions：

```text
Actions
→ Build Windows Release
→ Run workflow
→ 填写版本号，例如 v5.2.9
```

Release 流程：

```text
Checkout
↓
安装依赖
↓
语法 / import 检查
↓
pytest
↓
生成 Windows 图标
↓
PyInstaller 单文件打包
↓
生成 SHA256
↓
创建 GitHub Release
```

发布文件：

```text
InvoiceManager-Windows-x64.exe
SHA256SUMS.txt
```

普通代码提交不会再自动创建一堆新 Release。

版本号保持简单递增，例如：

```text
v5.2.8 → v5.2.9 → v5.2.10
```

较大功能更新可以进入：

```text
v5.3.0
```

详细流程见 `docs/RELEASE.md`。

## N. 当前限制

当前已知边界：

- 主要针对带可读取文字层的中国电子发票 PDF，不是通用 OCR 软件。
- QQ 邮箱当前只扫描 `INBOX`。
- 京东邮件解析依赖当前发件人、主题和 HTML 结构；京东改变邮件模板后可能需要适配。
- 购买匹配当前只使用价格。
- 同价记录较多时需要人工复核。
