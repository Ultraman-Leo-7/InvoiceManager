# InvoiceManager

**一个面向 Windows 的个人电子发票管理工具。**

InvoiceManager 把下面这套流程放进一个本地 GUI 中：

```text
发票收集 → PDF 解析 → 发票管理 → 购买记录 → 发票核对 → 数据备份 → Excel 导出
```

当前主要支持中国电子发票 PDF、QQ 邮箱中的京东电子发票、购买记录与价格核对，并提供坚果云 WebDAV 数据备份/恢复和手动程序更新。

## 下载

普通用户不需要安装 Python。

前往仓库 **Releases** 页面下载：

```text
InvoiceManager-Windows-x64.exe
```

把 exe 放到你的发票 PDF 文件夹中，双击即可运行。

> 当前 exe 没有商业代码签名证书，Windows 可能显示“未知发布者”或 SmartScreen 提示。

## 功能亮点

| 功能 | 说明 |
|---|---|
| PDF 发票管理 | 扫描当前目录中的电子发票 PDF，并提取常用字段 |
| 自动刷新 | 每 2 秒检测 PDF 的新增、删除和变化 |
| QQ 邮箱京东发票获取 | 使用 QQ 邮箱 + 16 位授权码批量获取京东电子发票 |
| 购买记录 | 记录商品名称、商品价格、是否有快递费及快递费金额 |
| 购买总金额 | 自动统计全部购买记录的商品价 + 快递费总金额 |
| 发票核对 | 默认按价格精确匹配，商品价与快递费分别匹配；支持手动调整关联 |
| 人工确认与备注 | 人工状态保存在 SQLite 中，不会因重新扫描 PDF 而重置 |
| 搜索与排序 | 搜索范围只跟随当前显示字段，点击表头升降序排序 |
| 多选与批量操作 | Ctrl / Shift 多选，支持批量确认、批量删除 |
| 坚果云备份 | 在“设置 → 备份与恢复”中配置一次，之后可按数据变化自动备份，也可从最新或历史备份恢复 |
| 本地安全备份 | 编辑/删除/清空购买记录前自动保存本地数据库快照 |
| 手动程序更新 | 在“设置 → 更新与关于”中手动检查；默认不自动检查或自动更新，并提供项目主页与 Star 入口 |
| Excel 导出 | SQLite 保存长期状态，Excel 只作为按需导出结果 |

## 设置界面

设置采用常见的左侧分类导航，避免把大量低频功能直接堆在主界面：

- **通用**：发票表显示字段，以及自动刷新 / Excel 导出的工作方式说明；
- **邮箱与发票**：QQ 邮箱和 16 位授权码；
- **备份与恢复**：坚果云账号、第三方应用密码、自动备份、测试连接、立即备份和恢复；
- **更新与关于**：当前版本、手动检查更新、GitHub 项目主页和 Star 入口。

主界面的 **更多** 菜单只保留真正的一键式低频操作：**设置、刷新发票文件夹、导出 Excel**。需要先配置参数的功能统一进入设置页。

## 数据安全原则

购买记录、人工确认、备注和设置都保存在：

```text
.invoice_manager.db
```

它和 exe 是分开的，所以：

- 替换或更新 exe 不会自动删除购买记录；
- 只删除 exe、保留数据库时，重新放入程序仍可继续使用原数据；
- 如果整个发票文件夹连数据库一起删除，本地数据当然也会丢失，因此建议配置坚果云备份；
- 购买记录的编辑、删除和“一键清空”前，程序会先创建本地安全快照；
- SQLite 写入使用事务，保存失败会显示错误，不会把“保存失败”伪装成成功。

**任何软件都不能承诺绝对不会发生磁盘损坏、用户误删或程序 Bug。** InvoiceManager 的策略是通过 SQLite + 本地安全快照 + 坚果云历史备份，把单点丢失风险尽量降低，并让用户能看到最近一次云备份结果。

## 隐私提醒

- 不要把自己的 PDF 发票、`.invoice_manager.db` 或包含真实隐私的截图上传到公开 Issue。
- QQ 邮箱授权码不会写进源代码，也不会上传到 GitHub。
- QQ 邮箱授权码和坚果云应用密码在 Windows 下使用 DPAPI 加密保存在本地数据库。
- 云端备份会主动移除这两个设备绑定的密钥，因此换电脑恢复后需要重新输入授权码/应用密码。
- 坚果云备份只上传程序数据库，不上传 PDF 发票本身。

详细说明见 `PRIVACY.md`、`SECURITY.md` 和 `docs/BACKUP.md`。

# 第一部分：小白快速使用

这一部分只讲怎么用。

## 1. 把程序放进发票文件夹

例如：

```text
发票文件夹/
├─ InvoiceManager-Windows-x64.exe
├─ 发票1.pdf
├─ 发票2.pdf
└─ ...
```

程序把 **exe 所在目录** 当作当前发票目录。

首次运行会自动创建：

```text
.invoice_manager.db
```

该数据库保存购买记录、设置、人工确认、备注等长期状态。

## 2. 查看本地发票

程序启动后自动扫描当前目录中的 PDF。

默认主要显示：

- 文件名
- 项目名称
- 价税合计
- 购买匹配
- 人工确认
- 备注

如果目录中新增、删除或替换 PDF，程序每 2 秒检查一次文件夹状态，检测到变化后自动刷新。

正常使用不需要手动刷新。为了减少主界面按钮，手动刷新已收进 **更多 → 刷新发票文件夹**，只在需要立即重新扫描时使用。

## 3. 设置 QQ 邮箱并获取京东发票

入口位于：

**更多 → 设置 → 邮箱与发票**

填写：

- QQ 邮箱
- QQ 邮箱 16 位授权码

这里使用的是 QQ 邮箱给第三方客户端生成的授权码，不是 QQ 登录密码。

保存以后：

- 授权码不会重新显示明文；
- 输入框保持空白表示继续使用已经保存的授权码；
- Windows 下授权码使用 DPAPI 加密保存在本机数据库。

回到主界面点击：

**从QQ邮箱获取京东发票**

可选择：

- 从上次成功获取之后；
- 自定义起始时间；
- 扫描全部历史收件箱。

自定义时间支持：

```text
YYYY-MM-DD
YYYY-MM-DD HH:MM
```

下载成功的京东发票会直接进入当前发票目录并参与解析。

## 4. 记录购买信息

切换到 **购买记录**。

例如：

```text
名称：数据线
商品价格：7.00
有快递费：否
```

或者：

```text
名称：背包
商品价格：74.00
有快递费：是
快递费：6.00
```

如果有快递费，程序把商品价和快递费视为两个独立的待匹配金额，而不是相加成一张发票。

购买记录支持：

- 新增；
- 编辑；
- 删除；
- Ctrl / Shift 多选删除；
- 一键清空全部；
- 自动显示全部购买记录的 **总金额**。

总金额计算规则：

```text
总金额 = 所有商品价格之和 + 所有已填写快递费之和
```

## 5. 购买记录会不会轻易丢失？

正常保存后，购买记录已经写入 SQLite 数据库，不依赖当前表格界面，也不依赖 Excel。

为了进一步降低误操作风险：

- 编辑已有购买记录前会自动创建本地数据库快照；
- 删除购买记录前会先创建本地数据库快照；
- 一键清空全部购买记录前也会先创建本地数据库快照；
- 如果本地安全备份创建失败，程序会直接取消这次破坏性操作，而不是继续删除；
- 本地快照放在 `.invoice_manager_backups` 目录中，默认保留最近 20 个；
- 配置坚果云后，可以进一步把数据库备份到云端，并保留历史版本。

因此，如果你准备把 InvoiceManager 当成购买记录的长期主记录，**建议至少配置一次坚果云自动备份，并偶尔确认“最近成功备份”时间正常更新。**

## 6. 配置坚果云备份

点击：

**更多 → 设置 → 备份与恢复**

填写：

- 坚果云账号邮箱；
- 坚果云第三方应用密码。

这里使用的是坚果云 WebDAV 的 **第三方应用密码**，不是坚果云登录密码。

推荐勾选：

**数据变化后自动备份到坚果云**

配置后可以：

- 测试连接；
- 立即备份；
- 自动备份数据变化；
- 从坚果云最新备份恢复；
- 从历史备份恢复。

云端默认创建：

```text
InvoiceManager/
├─ latest.db
└─ backups/
   ├─ InvoiceManager-时间戳.db
   └─ ...
```

程序目前保留最近约 30 个历史云备份。

### 云端到底备份什么？

会备份：

- 购买记录；
- 人工确认；
- 发票备注；
- 发票解析缓存；
- 显示字段设置；
- QQ 邮箱地址；
- 其他非敏感设置。

不会备份：

- PDF 发票文件本身；
- QQ 邮箱授权码；
- 坚果云应用密码。

后两项属于设备绑定密钥，换电脑恢复后重新输入即可。

### 恢复时怎么保护当前数据？

执行“从坚果云恢复”时，程序会：

1. 下载所选备份；
2. 先做 SQLite 完整性检查；
3. 自动备份当前本地数据库；
4. 再替换数据库；
5. 自动重启程序。

因此不会直接无备份覆盖当前数据库。

## 7. 手动检查程序更新

入口位于：

**更多 → 设置 → 更新与关于 → 检查更新**

设计原则是：

> **默认不自动检查更新，也不自动更新。**

只有你点击按钮以后，程序才会访问 GitHub Releases。

如果发现更高的正式版本：

1. 程序询问是否更新；
2. 下载新的 `InvoiceManager-Windows-x64.exe`；
3. 同时下载 `SHA256SUMS.txt`；
4. 本地验证 SHA256；
5. 校验通过后退出当前程序；
6. 替换旧 exe；
7. 自动重新打开新版。

更新只替换 exe，不会主动覆盖 `.invoice_manager.db`。

## 8. 搜索、排序和多选

发票页面的搜索范围会 **跟随当前实际显示的字段**。

例如设置里只显示“文件名、项目名称、价税合计”，搜索下拉框就只提供这些字段，再加上固定显示的“购买匹配、人工确认、备注”和“全部显示字段”。隐藏字段不会继续占据搜索菜单。

点击表头可切换升序/降序。

Windows 下：

- `Ctrl + 单击`：不连续多选；
- `Shift + 单击`：连续多选。

## 9. 手动调整发票关联

自动价格匹配出现错位时，在 **购买记录** 中选中一条记录，点击 **调整发票关联**。

可以分别针对：

- 商品；
- 快递费（如果该购买记录有快递费）

选择一张实际正确的发票并设为 **手动关联**。手动关联优先于自动价格匹配，即使存在多个同价发票，也会固定使用你指定的那张。

如果所选发票金额和购买记录金额不同，程序会额外确认，但仍允许人工指定。

点击 **恢复自动匹配** 后会删除这一人工覆盖关系，重新交给价格匹配算法分配。

一张发票最多只能被一个手动关联占用；手动调整前会创建本地安全快照，修改后也会参与坚果云自动备份。

## 10. 人工确认与备注

选中发票后可以使用：

- **人工确认标记**；
- **编辑备注**。

这些信息保存在 SQLite 中，不会因为重新扫描 PDF 自动清空。

如果配置了坚果云自动备份，修改人工确认或备注后也会触发数据备份。

## 11. 删除发票

**删除选中发票** 会实际删除当前发票目录中的 PDF，不只是从表格隐藏。

程序删除前会再次确认，并检查文件路径仍在当前发票目录内。

注意：当前发票删除没有程序内回收站。

## 12. 导出 Excel

点击：

**更多 → 导出 Excel**

生成：

```text
发票汇总.xlsx
```

其中包含：

- 发票汇总 Sheet；
- 购买记录 Sheet。

Excel 是导出结果，不是主数据库。

# 第二部分：完整功能与实现细节

## A. 当前目录与 PDF 自动刷新

- exe 所在目录就是发票目录；
- 当前目录中的 `*.pdf` 是当前有效发票数据源；
- 启动后自动扫描；
- 每 2 秒检查一次 PDF 文件名、大小和修改时间；
- 检测到新增、删除或变化后自动刷新；
- 手动刷新属于低频操作，放在“更多 → 刷新发票文件夹”中。

### PDF 刷新规则

- 新增 PDF：解析并加入列表；
- 内容未变化：复用数据库缓存；
- 内容变化：重新解析自动字段；
- 文件改名但内容相同：通过 SHA256 内容哈希识别；
- PDF 离开目录：标记为当前不活跃；
- 同内容 PDF 再放回：可继续复用原数据库信息，包括人工确认和备注。

## B. PDF 解析

程序通过 PyMuPDF 读取 PDF 的文字层和坐标信息。

当前不是通用 OCR，因此最好使用带可读取文字层的中国电子发票 PDF。

可提取字段包括：

- 文件名
- 发票号码
- 开票日期
- 购买方名称
- 销售方名称
- 项目名称
- 价税合计
- 金额（不含税）
- 税额
- 开票人
- 提取状态

默认显示：文件名、项目名称、价税合计；GUI 另外固定显示购买匹配、人工确认、备注。

## C. SQLite 主数据库

内部主数据库：

```text
.invoice_manager.db
```

主要保存：

- 发票解析缓存；
- 人工确认；
- 备注；
- 购买记录；
- QQ 邮箱设置；
- 坚果云设置；
- 用户选择的显示字段；
- 最近成功获取/备份状态。

Excel 不承担长期状态存储。

## D. 购买记录持久化与安全保护

购买记录每次新增/修改都在 SQLite 事务中完成。

对于会覆盖或删除已有购买数据的操作，程序先使用 SQLite Backup API 创建一致性本地快照：

```text
.invoice_manager_backups/
```

当前保留最近 20 个本地安全快照。

如果安全快照创建失败，编辑/删除/清空操作会被阻止。

购买页摘要显示：

```text
购买 N 项 | 总金额 ¥X.XX | 缺票 N 项 | 未对应发票 N 张
```

总金额包含商品价以及有快递费记录中的快递费。

## E. 价格匹配规则

当前购买记录和发票 **只按价格匹配**。

不会使用：

- 商品名称；
- 商家名称；
- 日期；
- 订单号。

商品价与快递费是两个独立组成项。

一张发票最多匹配一个组成项，一个组成项最多匹配一张发票。

存在多个完全相同价格时，自动规则按购买记录 ID 和发票文件名顺序确定配对。

用户可以为某个购买组成项建立 **手动发票关联**。手动关联优先于自动价格匹配，并会提前占用对应发票；其他购买记录再从剩余发票中自动匹配。恢复自动匹配后，该人工覆盖关系被删除。

## F. QQ 邮箱京东发票获取

当前：

```text
QQ 邮箱 -> 京东电子发票
```

使用：

```text
imap.qq.com:993
SSL/TLS
```

当前只扫描 `INBOX`。

京东邮件筛选主要依赖：

- 发件人 `customer_service@jd.com`；
- 主题包含“电子发票已开具”；
- HTML 中的“发票PDF文件下载”链接。

下载后验证响应以 `%PDF-` 开头，并使用 SHA256 去重。

每个下载请求当前最多重试 3 次。

## G. 授权码安全

QQ 邮箱授权码和坚果云 WebDAV 应用密码：

- 不写入源代码；
- Windows 下使用 DPAPI 加密后保存；
- 设置界面不回显已经保存的明文；
- 云端数据库快照会删除这些密钥字段。

因此云备份可以跨电脑恢复普通数据，但密钥需要在新电脑重新输入。

## H. 坚果云 WebDAV 备份

程序直接使用标准 WebDAV 访问坚果云。

备份前不是直接复制正在使用的数据库文件，而是使用 SQLite Backup API 生成一致性快照，然后再上传。

上传内容包括：

- `latest.db`：最近一次备份；
- `backups/InvoiceManager-时间戳.db`：历史备份。

恢复前执行：

```text
下载 -> SQLite integrity_check -> 本地安全备份 -> 替换 -> 重启
```

这样可以降低“云端文件损坏后直接覆盖本地”的风险。

自动备份开启以后，购买记录、人工确认、备注、普通设置变化会触发云端备份。

自动备份失败时，状态栏会显示失败信息，并把最近失败原因保存在本地设置中；“数据备份”窗口可以查看最近成功时间和最近失败信息。

## I. 手动自更新

程序启动时 **不联网检查更新**。

只有通过“更多 → 检查更新”主动执行后才访问本项目 GitHub Releases。

只识别简单正式版本号：

```text
v5.2.9
v5.2.10
v5.3.0
```

不会使用 beta 版本规则。

下载更新时必须同时取得 exe 和 `SHA256SUMS.txt`，本地 SHA256 匹配后才执行替换。

Windows 自更新通过独立 PowerShell 进程等待当前 exe 退出，再替换原程序并重新打开，可处理包含中文字符的本地路径。

## J. 搜索、排序、多选

发票搜索范围只包含当前可见字段；“全部显示字段”也只搜索当前显示列，不再搜索被设置隐藏的字段。

金额搜索会格式化为两位小数。

发票表、购买主表、缺票表和未对应发票表都支持点击表头排序。

发票和购买主表支持 Ctrl/Shift 多选。

## K. Excel 导出

导出文件：

```text
发票汇总.xlsx
```

发票 Sheet 包含用户选择字段 + 购买匹配 + 人工确认 + 备注。

购买记录 Sheet 包含名称、价格、快递费和匹配结果。

如果 Excel/WPS 正占用同名文件，程序会提示关闭后重试。

## N. 当前已知限制

- 主要针对带文字层的中国电子发票 PDF，不是通用 OCR；
- QQ 邮箱当前只扫描 INBOX；
- 京东邮件格式改变后可能需要更新解析规则；
- 购买匹配只看价格，同价记录仍需要人工复核；
- 坚果云备份不包含 PDF 发票本身；
- 云端备份不会携带 QQ/坚果云应用密码；
- 当前主要发布 Windows x64 单文件 exe；
- exe 尚未商业代码签名。
